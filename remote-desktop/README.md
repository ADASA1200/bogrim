# RDesk – שליטה מרחוק בסגנון AnyDesk

תוכנת שולחן עבודה מרוחק קוד-פתוח, כתובה ב-Python על בסיס **WebRTC**.
וידאו, עכבר, מקלדת, לוח, קבצים וצ'אט עוברים **ישירות בין המחשבים (P2P)**, מוצפנים (DTLS‑SRTP),
והשרת משמש רק לאיתות (הכרות בין שני הצדדים).

**הממשק הוא דף React** שרץ בתוך חלון דפדפן מקומי ([pywebview](https://pywebview.flowrs.dev/))
ולא Tkinter - RTL עברי תקין ומעוצב, בלי ה"האק" שהיה נדרש עם Tk. כל לוגיקת הליבה (חיבור, הצפנה,
לכידת מסך, הזרקת קלט) נשארת ב-Python בדיוק כפי שהייתה; רק שכבת התצוגה חדשה.
ל-tkinter הישן יש fallback: `--legacy-ui`.

```
 צופה  ───── שרת איתות (WebSocket, הודעות SDP בלבד) ─────  מארח
   └────────── חיבור P2P מוצפן (STUN) / TURN כגיבוי ─────────┘
```

## אפליקציות

| פלטפורמה | מה זה | איך משיגים |
|---|---|---|
| **Windows (התקנה)** | `RDesk-Setup.exe`: תוכנת התקנה רגילה - קיצור בתפריט התחלה, אייקון לשולחן העבודה (אופציונלי), מופיעה ב"הסרת התקנה" כמו כל תוכנה | GitHub Actions: *Actions → build-windows-exe → Run workflow*, מורידים את `RDesk-windows-installer` מה-Artifacts |
| **Windows (נייד)** | `RDesk.exe`: אותה תוכנה, בלי התקנה - קובץ בודד שרצים ישירות | אותה הרצה, `RDesk-windows-portable`. או מקומית: `python build_exe.py` |
| **אנדרואיד** | `RDesk.apk`: מתקינים ישירות על הטלפון (APK הוא כבר קובץ התקנה). צופה - שולטים במחשב מהטלפון, עם מגע כטאצ'פד ומקלדת | *Actions → build-android-apk → Run workflow*, מורידים את `RDesk-android` (`app-debug.apk`). או מקומית: `cd ../android && ./gradlew assembleDebug` |

שתי התוכנות ל-Windows (ההתקנה והנייד) מריצות בדיוק אותו `RDesk.exe` מבפנים - ההבדל הוא רק אם יש
תהליך התקנה/הסרה מסודר או לא. אפליקציית האנדרואיד תמיד "מותקנת" - ככה APK עובד.

- את התוכנות צריך לכוון לשרת האיתות שלכם: משתנה ה-repository `RDESK_SERVER` (*Settings → Secrets and variables → Actions → Variables*, למשל `wss://signal.example.com`) נשתל בעת הבנייה. אפשר גם לשנות בהגדרות התוכנה/האפליקציה.
- **שימו לב:** GitHub מציג workflow בלשונית Actions רק אחרי שהקובץ נמצא בענף הראשי (main/master). מיזגו את הענף לפני שמריצים.
- התקנת APK מחוץ ל-Play דורשת לאשר "התקנה ממקורות לא ידועים".
- אפליקציית האנדרואיד היא **צופה בלבד** (שולטת במחשב). שליטה *בטלפון* מהמחשב לא נתמכת עדיין.
- ההתקנה (`RDesk-Setup.exe`) לא דורשת הרשאות מנהל - מתקינה לתיקיית המשתמש. ה-EXE עצמו (גם בגרסה הנייד
  וגם מתוך ההתקנה) לא חתום דיגיטלית, אז Windows SmartScreen עשוי להזהיר: "מידע נוסף" ← "הפעל בכל זאת".

## איך החיבור עובד (כמו ב-AnyDesk)

1. במחשב הנשלט (**מארח**) מוצג **מזהה** בן 9 ספרות.
2. הצופה מקליד את המזהה ולוחץ "התחבר".
   - **בלי סיסמה:** במארח קופץ חלון *"מישהו מבקש להתחבר למחשב שלך"*. המשתמש מאשר (ובוחר הרשאות) או דוחה. מספיק מזהה.
   - **עם סיסמת גישה ללא נוכחות:** אם בעל המחשב הגדיר במארח סיסמה קבועה, הצופה יכול להקליד אותה (לצד המזהה) והחיבור מתבצע **בלי אישור**.
     אם לא הוגדרה סיסמה כזו, או שהצופה לא הקליד אותה, פשוט מחכים לאישור המשתמש.
3. בכל סשן מוצג בשני הצדדים **קוד אבטחה** (6 ספרות). אם הוא זהה, אין מתווך באמצע.

## מצב "בלי שרת נפרד" (המחשב עצמו משמש כשרת)

ברירת המחדל דורשת שרת איתות שרץ במקום נגיש לשני הצדדים. אם אין לכם כזה, אפשר
לוותר עליו לגמרי: **המחשב הנשלט (המארח) מריץ את שרת האיתות בתוך עצמו.**

- ב-RDesk.exe / `python -m rdesk`: לשונית **הגדרות** → "המחשב הזה כשרת" → מסמנים
  את התיבה, שומרים, ומפעילים מחדש. בלשונית הראשית יופיעו הכתובות לתת לצד השני:
  - **ברשת המקומית** (בית/משרד): עובד מיד, בלי הגדרות נוספות בנתב.
  - **מהאינטרנט**: צריך להגדיר **הפניית פורט (Port Forwarding)** בנתב של המחשב
    הזה - להפנות את הפורט (ברירת מחדל 8765) אל ה-IP הפנימי של המחשב, ולתת לצד
    השני את ה-IP ה*ציבורי* שמוצג שם.
- בשורת פקודה (גם בלינוקס/macOS): `python -m rdesk host --headless --serve-signaling`
  (אפשר גם `--serve-signaling 9000` לפורט מסוים).
- הצד השני (צופה, EXE או אנדרואיד) מזין בשדה "שרת" את הכתובת שקיבל, למשל
  `ws://192.168.1.50:8765` (LAN) או `ws://<IP ציבורי>:8765` (אינטרנט), ואז את
  המזהה של המארח כרגיל.

זה לא "שרת חינמי" קסום - מישהו עדיין צריך לארח את נקודת ההכרות, רק שעכשיו זה
המחשב שלכם במקום תהליך נפרד. בפעם הראשונה ש-Windows Firewall שואל אם לאפשר
ל-RDesk גישת רשת - יש לאשר, אחרת אף אחד לא יגיע לשרת המוטבע.

## התקנה

```bash
cd remote-desktop
pip install -r requirements.txt      # Python 3.10+
cd webui && npm ci && npm run build && cd ..    # בונה את ממשק ה-React (חד-פעמי; מתעדכן אחרי כל שינוי ב-webui/src)
```
**Windows:** ה-UI רץ בתוך WebView2 (מגיע מובנה ב-Windows 11 ומותקן אוטומטית ע"י Edge ב-Windows 10 - כמעט
תמיד כבר קיים). **Linux:** צריך `gir1.2-webkit2-4.1` ו-`gir1.2-gtk-3.0` (`apt install`).

## הרצה

1. **שרת איתות** (על מחשב נגיש לשני הצדדים; בבדיקה מקומית – אותו מחשב; או ראו
   "מצב בלי שרת נפרד" למטה כדי לוותר על השלב הזה לגמרי):
   ```bash
   python -m rdesk server --host 0.0.0.0 --port 8765
   ```
2. **במחשב שרוצים לשלוט בו (מארח):**
   ```bash
   python -m rdesk host --server ws://SERVER_IP:8765
   ```
   יוצג המזהה. בלשונית "הגדרות" אפשר להגדיר סיסמה קבועה לגישה ללא נוכחות (לפחות 8 תווים)
   ולבחור אילו הרשאות יינתנו למי שמתחבר איתה.
   בלי ממשק גרפי: `--headless`; את הסיסמה הקבועה מגדירים עם `python -m rdesk unattended` (וכיבוי עם `--off`).
3. **במחשב ממנו שולטים (צופה):** בלי פקודה, `python -m rdesk` פותח את **האפליקציה המלאה** (כמו ה-EXE):
   חלון אחד עם המזהה שלכם (כמארח), תיבת "התחברות למחשב אחר", ולשונית הגדרות (גישה ללא נוכחות ושרת).
   מקלידים מזהה (סיסמה היא אופציונלית) ולוחצים "התחבר". אפשר גם `python -m rdesk viewer` לצופה בלבד.

הגדרות נשמרות ב-`~/.rdesk/config.json`. אם אין STUN זמין (רשת פנימית), `RDESK_STUN=""` מדלג עליו ומאיץ את ההתחברות.
הוסיפו `--legacy-ui` לכל אחת מהפקודות האלה כדי להריץ את ממשק ה-Tkinter הישן במקום ה-React.

### פריסה לאינטרנט
- הריצו את שרת האיתות מאחורי TLS (`--certfile/--keyfile` או reverse proxy) וחברו עם `wss://`.
- חיבור P2P מצליח ברוב הרשתות. לרשתות קשות (NAT סימטרי) הקימו
  [coturn](https://github.com/coturn/coturn) והעבירו `--turn turn:host:3478,user,pass` למארח.

### בניית קובץ EXE ל-Windows (נייד)
```bash
cd webui && npm ci && npm run build && cd ..
pip install pyinstaller
python build_exe.py
```
build_exe.py בודק ש-`webui/dist` קיים, אורז אותו לתוך ה-EXE, ומגדיר את ה-`--collect-all` הדרושים
ל-pywebview/aiortc/sv_ttk. שנו את `DEFAULT_SERVER` ב-`rdesk/protocol.py` לכתובת השרת שלכם לפני הבנייה,
או השתמשו במשתנה `RDESK_SERVER` ב-GitHub Actions (ראו `.github/workflows/build-windows-exe.yml`).

```bash
cd webui && npm run dev
```
פותח שרת פיתוח עם hot-reload בכתובת `http://localhost:5173` (עם נתוני דמה - בלי pywebview אמיתי).
כדי לבדוק מול ה-backend האמיתי צריך לבנות (`npm run build`) ולהריץ את `python -m rdesk`.

## חיבור ברשת עם סינון/בקרת תוכן

ברירת המחדל של Python משתמשת ברשימת אמון פנימית קבועה ולא בחנות התעודות של
מערכת ההפעלה. זה אומר שאם מותקנת במחשב תוכנת אבטחה/סינון שמוסיפה תעודת
root משלה (בדיוק כפי שדפדפנים "סתם עובדים" איתה), חיבור ה-`wss://` עלול
להיכשל גם כשהתעודה כבר מוגדרת כמהימנה במערכת. RDesk פותר את זה באמצעות
[truststore](https://pypi.org/project/truststore/): חיבור ה-wss:// קורא
ישירות מחנות התעודות של Windows/macOS, בדיוק כמו דפדפן - **בלי לשנות שום
דבר באימות עצמו ובלי להוסיף אמון לשום תעודה בעצמו.**

זה לא עוזר לתעבורת הווידאו/קלט (WebRTC P2P על UDP) - שום תוכנת סינון לא
יכולה "להסתכל" בתוכן של שיחת WebRTC מוצפנת, בדיוק כמו שיחת זום. אם רשת
חוסמת UDP, הפתרון היחיד הוא TURN-over-TLS בפורט 443 (`--turn`), וגם זה
דורש שמנהל הרשת יאפשר אותו - אין שום דרך "לעקוף" חסימה בשקט, וגם לא ננסה.

## אבטחה

- **הצפנה מקצה לקצה:** DTLS‑SRTP של WebRTC. השרת לא רואה וידאו, קלט או קבצים.
- **המארח תמיד שולט:** בחיבור רגיל, שום דבר לא קורה בלי אישורו. תמיד מוצג מחוון "סשן פעיל" (גם בגישה ללא נוכחות),
  עם כפתור ניתוק, והרשאות שניתנות לביטול. ההרשאות נאכפות בצד המארח ולא נסמכות על הלקוח.
- **סיסמת גישה ללא נוכחות:** נשמרת בדיסק רק כמפתח נגזר (PBKDF2), לא כטקסט. היא אף פעם לא נשלחת ברשת:
  ה-SDP (כולל טביעת האצבע של DTLS) נחתם ב-HMAC‑SHA256 עם nonce חד-פעמי, ולכן גם שרת איתות עוין לא יכול להתחזות.
  מומלצת סיסמה ארוכה וייחודית.
- **חיבור באישור, בלי סיסמה:** אין חתימה על ה-SDP, ולכן מסתמכים על שרת האיתות שלכם (מומלץ `wss://` על שרת שלכם)
  ועל **קוד האבטחה** שמוצג בשני הצדדים: קוד שונה = מישהו באמצע.
- הגנות: חסימה של דקה אחרי 5 סיסמאות קבועות שגויות ואחרי 3 דחיות רצופות (מניעת הצפת חלונות אישור),
  ולידציה של כל אירוע קלט, הגנת path traversal בקבצים, מגבלות גודל ו‑rate‑limit בשרת.

> השתמשו רק במחשבים שלכם או כאלה שיש לכם הרשאה מפורשת לשלוט בהם. אל תעבירו את הסיסמה הקבועה למי שלא בוטחים בו.

## בדיקות
```bash
python -m pytest -q              # 31 בדיקות (צריך pywebview מותקן בשביל test_webapp.py)
cd ../android && ./gradlew testDebugUnitTest   # 7 בדיקות: ה-Kotlin מול וקטורים שנוצרו ב-Python
```
בדיקות ה-`test_browser_interop` מריצות צופה ב-Chromium (אותו libwebrtc כמו באנדרואיד) מול המארח האמיתי
(דורש node + playwright, אחרת מדלג). בדיקות ה-`test_webapp` מריצות את הגשר של React (HostAPI/ViewerAPI)
מקצה לקצה - אישור, הקמת WebRTC, הזרמת וידאו, צ'אט, הרשאות, ניתוק - בלי חלון אמיתי (push מוקלט במקום
evaluate_js). בדיקה נפרדת, ידנית, עם WebKitGTK/WebView2 אמיתי ושני חלונות ממש, אימתה גם את זה.

18 בדיקות מקצה לקצה נוספות (בלי תצוגה גרפית): חיבור באישור, גישה ללא נוכחות, סיסמה שגויה וחסימה,
דחייה והצפה, קוד אבטחה, צפייה בלבד, שני צופים (busy), צ'אט, לוח, איכות, קבצים והרשאות, ושמירת הגדרות.
